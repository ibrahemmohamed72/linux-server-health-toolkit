# Linux Server Health Check + Shell Automation Toolkit

A lightweight, dependency-free toolkit for monitoring the health of a Linux
server: disk space, memory/swap, and systemd service status — with automatic
log rotation and a daily Markdown report generated by a small Python script.
Designed to run standalone or on a cron schedule with zero external
dependencies beyond `bash`, `coreutils`, and `python3`.

## Features

- **Disk space check** — flags any mounted filesystem crossing configurable
  warning/critical usage thresholds.
- **Memory & swap check** — flags high RAM and swap usage.
- **Service check** — verifies that a configurable list of systemd services
  (e.g. `sshd`, `nginx`, `cron`) is active.
- **Log rotation** — compresses and expires the toolkit's own logs (and
  optionally any other log directory you point it at).
- **Daily report generator** (Python) — parses the structured results from
  every check and produces a single readable Markdown report with an
  overall health status.
- **Cron-ready** — a master script (`run_all_checks.sh`) runs everything in
  one shot; example crontab entries included.
- **Structured data** — every check appends a JSON line to
  `logs/data/*.jsonl`, so results are easy to feed into other tooling
  (Grafana, a dashboard, alerting scripts, etc.) beyond the bundled report.

## Architecture

```
                 ┌─────────────────────┐
     cron  ───▶  │ run_all_checks.sh   │
                 └──────────┬──────────┘
                            │
        ┌───────────────────┼───────────────────┬─────────────────┐
        ▼                   ▼                   ▼                 ▼
 check_disk.sh      check_memory.sh     check_services.sh    log_rotate.sh
        │                   │                   │
        └───────────────────┴───────────────────┘
                            │  appends JSON lines
                            ▼
                  logs/data/*_results.jsonl
                            │
                            ▼
              python/generate_report.py
                            │
                            ▼
               reports/report-YYYY-MM-DD.md
```

Every check script is independent and can be run on its own, on its own
schedule, with its own exit code (`0` = OK, `1` = warning present, `2` =
critical present) — handy for wiring into existing alerting systems.

## Requirements

- Linux with `bash` (tested on Ubuntu/Debian; `systemctl` checks are skipped
  gracefully on non-systemd systems)
- Standard coreutils: `df`, `free`, `awk`, `gzip`, `find`
- `python3` (standard library only — no pip install required)
- `cron` (optional, for scheduling)

## Installation

```bash
git clone https://github.com/<your-username>/linux-server-health-toolkit.git
cd linux-server-health-toolkit
./install.sh
```

`install.sh` will:
1. Make all scripts executable
2. Create the `logs/` and `reports/` directories
3. Optionally install a daily 7:00 AM cron job for you

## Usage

Run everything (checks + log rotation + report) in one go:

```bash
./scripts/run_all_checks.sh
```

Or run an individual check:

```bash
./scripts/check_disk.sh
./scripts/check_memory.sh
./scripts/check_services.sh
./scripts/log_rotate.sh
```

Generate a report manually for a specific date:

```bash
python3 python/generate_report.py \
  --data-dir logs/data \
  --report-dir reports \
  --date 2026-07-19
```

Reports are written to `reports/report-YYYY-MM-DD.md`. See
[`sample_output/sample_report.md`](sample_output/sample_report.md) for an
example.

## Configuration

All thresholds and settings live in [`config/health_check.conf`](config/health_check.conf):

| Setting | Description | Default |
|---|---|---|
| `DISK_WARN_THRESHOLD` / `DISK_CRIT_THRESHOLD` | Disk usage % that triggers warning/critical | 75 / 90 |
| `MEM_WARN_THRESHOLD` / `MEM_CRIT_THRESHOLD` | RAM usage % that triggers warning/critical | 80 / 95 |
| `SWAP_WARN_THRESHOLD` | Swap usage % that triggers a warning | 50 |
| `SERVICES_TO_CHECK` | Space-separated systemd unit names to monitor | `sshd cron` |
| `LOG_ROTATE_TARGET_DIR` | Extra log directory to rotate, beyond the toolkit's own | _(empty)_ |
| `LOG_ROTATE_MAX_AGE_DAYS` | Days before a compressed log is deleted | 7 |

Edit this file to match your server before deploying.

## Scheduling with cron

See [`cron/crontab_example.txt`](cron/crontab_example.txt) for ready-to-edit
entries, e.g.:

```cron
# Run all checks + generate report every day at 7:00 AM
0 7 * * * /opt/linux-server-health-toolkit/scripts/run_all_checks.sh >> /opt/linux-server-health-toolkit/logs/cron.log 2>&1
```
